# To Spec

Convert conversational discussion and requirements into structured technical specs.

## When to Use
- Following a discovery or grill-me session.

## Core Protocol / Capabilities
1. Identify user persona, problem, and non-goals.
2. Document architecture choices and interfaces.
3. Produce a markdown SPEC document.

## Anti-Patterns & Warnings
- Leaving requirements ambiguous.
- Omitting non-goals.
