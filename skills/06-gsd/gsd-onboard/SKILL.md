# Gsd Onboard

Onboard an existing codebase; map architecture, quality, and technical debt.

## When to Use
- Introducing GSD to an established repository.

## Core Protocol / Capabilities
1. Run codebase mapping passes (tech, arch, quality, concerns).
2. Synthesize findings into `.planning/` documentation.
3. Formulate initial remediation roadmap.

## Anti-Patterns & Warnings
- Rewriting existing architecture blindly.
- Ignoring undocumented edge cases.
